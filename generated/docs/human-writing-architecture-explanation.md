# 架构图说明

配套文件 `human-writing-architecture.html`。本文解释这张图画的是什么、每个框代表什么、连线怎么读。

## 前提：这个仓库没有服务端

`human-writing` 不是一个网站或后端服务，它是一个「AI 写作规则包」。仓库里只有 Markdown 规则文件、一个 Python 检查脚本和一份蒸馏版说明，没有可运行的服务器代码。

所以这张图画的是「运行时」，指的是另一件事：当你在 Claude Code 或类似 Agent 里说「帮我写一篇文章」时，整套系统是怎么转起来的。参与者有三个：你、Agent 宿主（比如 Claude Code）、装进 Agent 的这个 Skill 包。图里的箭头不是网络请求，而是「谁触发谁、谁读谁」的控制流和读取关系。

## 一句话概括

用户发出写作请求 → Agent 加载 Skill 入口 → 入口按任务类型分流读取规则文件 → 写完初稿后走改稿清单 → 检查脚本扫硬禁令，不通过就打回重改，通过才交稿。

## 怎么打开图

用浏览器直接打开 `human-writing-architecture.html`，不需要网络和本地服务器。打开后可以用：

- 主题切换（亮色 / 深色）
- 搜索、聚焦某个组件
- 三个导览视图（见下文「导览视图」一节）
- 导出 PNG / SVG

## 节点逐个解释

图上一共 12 个框，分三类：外部（虚线风格）、本机 Agent 环境、Skill 包内部。

### 入口和主路径上的框

| 框 | 是什么 |
| :--- | :--- |
| 用户 | 发写作请求、提供材料的人。请求里通常带文体（知乎回答、小说、演讲稿）和素材。 |
| Agent 宿主 | Claude Code 或 IDE Agent。它负责加载 Skill、把规则喂给模型、执行脚本。 |
| SKILL.md 入口 | 整个 Skill 的编排核心。先做材料门槛检查（非虚构长文列不出五件具体材料就不动笔），再决定读哪些参考文件，最后执行交付禁令。 |
| 长帖散文规则 | `references/forum-prose.md`。知乎、公众号、论坛长帖的具体写法，是默认必读的那份。 |
| 改稿清单 | `references/revision.md`。初稿完成后才加载，逐遍检查重复、节奏和违禁句式。 |
| 禁令检查脚本 | `scripts/check_prose.py`。本地 Python 脚本，扫描成稿里的硬禁令（冒号、破折号、翻案句、黑话），失败返回非零退出码。 |

### 分流读取的三个规则文件

这三个框都挂在 SKILL.md 上方，按任务性质「加读」，不每次全读：

| 框 | 什么时候读 |
| :--- | :--- |
| 现实事实边界 `reality.md` | 写真人、历史、新闻、数据时。管事实核验和来源要求。 |
| 虚构创作规则 `fiction.md` | 写小说、故事、对白时。管人物、因果和场景推进。 |
| 特殊形式规则 `formats.md` | 写口播、演讲、教程、评测等特殊体裁时。 |

### 边界外的三个框

| 框 | 是什么 |
| :--- | :--- |
| GitHub Releases | 安装来源。整个 Skill 包从 GitHub 仓库装到本机 `~/.agents/skills/` 目录。 |
| 蒸馏版 Lite | `dist/human-writing-lite.md`，约两千字的规则浓缩版，属于导出产物，不参与本机流程。 |
| 聊天窗口 | ChatGPT、千问等不支持加载 Skill 的产品。把蒸馏版内容粘进去，就能在弱环境下用五条核心规则。 |

## 主路径怎么读

图里加粗的箭头就是主路径，从左到右：

1. 用户把写作请求交给 Agent 宿主（「写作请求」）
2. Agent 加载 SKILL.md（「加载 Skill」）
3. 入口按任务读取散文规则（「按任务读取」）
4. 初稿写完，进入改稿清单（「初稿完成后」）
5. 改完交给检查脚本（「硬禁令检查」）
6. 脚本报错就沿虚线回到改稿清单（「未清零 · 修改重查」），循环到清零为止

其余箭头都是支线：三条向上的「加读」虚线分支、GitHub 安装线、蒸馏版粘贴线。支线一律从主路径最近的节点出发，这是刻意安排的，避免满屏交叉线。

## 两个边界框是什么意思

- 外层「本机 Agent 运行环境」：Agent 宿主和整个 Skill 包都在你本机的 `~/.agents/skills/` 目录下运转，不依赖云端部署。
- 内层「human-writing 包 · 规则信任边界」：包内 7 个组件共享同一套规则约定，边界内的规则文件互相引用、互相覆盖（有明确的优先级顺序），边界外的组件只做触发和消费。

## 底部三张卡片

连线之外的支持性细节都收在卡片里，不画进图：

- 写作主路径卡片：材料门槛的具体规则、参考文件按需加载、检查脚本清零才交稿
- Skill 包内卡片：五个 references 的分工、检查器只管硬禁令不管风格、交稿只交作品
- 边界之外卡片：GitHub 是唯一安装来源、蒸馏版的用途、不建作者画像的约束

## 导览视图

HTML 顶部有三个预设视图按钮，对应三种看法：

| 视图 | 聚焦什么 |
| :--- | :--- |
| 写作主路径 | 用户到检查脚本那条加粗链路 |
| 规则分流 | SKILL.md 和它上方三个规则文件 |
| 分发与降级 | GitHub 安装线和蒸馏版粘贴线 |

想整体理解系统就按顺序看这三个视图，比一次读全图省力。
